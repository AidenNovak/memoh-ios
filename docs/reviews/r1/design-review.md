# Memoh iOS 设计评审 R1

评审对象：R1 真机截图（iPhone，402pt 宽逻辑屏，浅色 + 深色）。
测量基准：`small-*.png` 为 414×900，1px ≈ 1pt，文中数值为实测或按实测推算。

---

## 0. 总体结论

这版的问题不是"丑"，是**没有用到 iOS 的材质与层级系统**：所有容器都是等灰度
的纯色块，分隔线全宽、导航栏不透明、按钮没有状态色、间距体系不成比例。看
起来像"渲染正确的 HTML"，而不是 UIKit 长出来的界面。

三个屏里对话页离合格最远（它是核心屏），登录页最近。下面逐屏说。

---

## 1. 逐屏诊断

### 1.1 登录页

**层级与间距：组间距离 < 组内距离，这是最大的错误。**

实测：

```
标题 "Sign in"        32pt Bold        y≈262
副标题说明            15pt 灰          y≈310   ← 距标题 16pt ✓
[SERVER 标签]         11pt 灰          y≈352   ← 距副标题 ~42pt
[输入框]              高 45pt          y≈374–419  ← 标签距框 ~12pt
[USERNAME 标签]                        y≈430   ← 上一个框距它只有 ~11pt !!
```

问题：**框到下一个标签的距离（11pt）比标签到自己框的距离（12pt）还小**，
眼睛的自动分组会把标签归到上面那个框。这是"看着别扭"的直接原因。

- 标签 → 自己的框：**6pt**（贴紧）
- 框 → 下一组标签：**24pt**
- 副标题 → 第一组：**28pt**

**"全大写标签悬浮在框上方"是 Web/Material 模式。** iOS 的原生做法是二选一：

a) **分组表单（Settings 风，推荐）**——一张 inset 16pt 的圆角卡片内含三行，
行高 44pt，行内左侧标签 17pt（如"服务器"）、右侧或下方是值，行间
0.5pt 分隔线左缩进 16pt：

```
┌────────────────────────────────────────┐
│  服务器      http://127.0.0.1:18080    │
│ ────────────────────────────────────── │
│  用户名      aiden                     │
│ ────────────────────────────────────── │
│  密码        ••••••••                  │
└────────────────────────────────────────┘
```

b) Apple ID 风：无边框，标签 13pt 常规灰，框只有底线。不要现在的
"圆角白块 + 全大写标签"混血。

**Sign in 按钮的禁用态不合格。** 实测灰底 (226,226,232) + 灰字，对比度约
1.6:1，看起来像坏掉了。iOS 惯例：

- 禁用：品牌紫底 + 白字 **40% 不透明度**（整体 alpha 0.4），仍可辨认是主按钮；
- 或者干脆常亮，点了再校验并抖出错误（Apple 自家表单常用）。
- 按钮高 50pt、圆角 12（现在的 52/14 可以接受）、距上一组 **32pt**。

其余：

- 服务器框应该用 URL 键盘（无空格键、带 `.` `/`），密码框开 secure entry +
  `textContentType=password` 以接 Password AutoFill——这是"像原生"的隐藏分。
- 深色模式背景纯黑 (0,0,0) 是对的（systemGroupedBackground），但框色
  应该用 secondarySystemGroupedBackground（≈#1C1C1E），实测偏亮。
- 缺错误态设计：连不上服务器 / 401 时怎么办（见 §2.6）。
- 顶部留白太多（标题从 y≈262 才开始），键盘弹出时整个表单应能上移，
  标题可缩至 28pt 或隐藏副标题。

### 1.2 首页（会话列表）

**浅色截图暴露的空态 = 零信息量 + 一个悬空的菊花。** 列表为空时屏幕中央
上方有一个巨大的 spinner（y≈90），旁边标题右边一行 "Reconnecting…"。
用户不知道：这是什么列表、为什么是空的、能干什么。修复见 §2.1/§2.5。

**顶部结构散乱，浪费了两行纵向空间。** 深色实测：

```
y≈70   [● iOS Dev]          ← bot 胶囊，孤零零一行
y≈118  Sessions      ● Online  ← 大标题 + 状态，又一行
y≈171  列表开始
```

导航信息（在哪个 bot）占了整整 40pt 的独立行。iOS 惯例：这是**导航栏标题**
的职责——大标题 "Sessions" 左侧或下方做一个 13pt 副标题（标题 + 人形/
机器人图标 + 名字），或用 iOS 16+ 的标题菜单（标题右侧 `chevron.up.chevron.
down`，点了切换 bot）。状态点收缩为导航栏右侧一个小圆点（绿/橙/红）。

**列表行结构不对。** 实测行高 64pt，标题 17pt 在上、时间戳 13pt 灰在下，
右半侧全空；**分隔线全宽贯通**（实测一直画到 x=390）。

- 时间戳应该**右上对齐**（Messages/邮件惯例），副标题位置让给**最后一条
  消息预览**——现在列表无法区分任何一行，"Verify chat × 4、iOS smoke × 5"
  恰好证明了这一点。
- 分隔线：0.5pt、systemSeparator、**左缩进 16pt**（有头像则缩进到文字起点）。
- 会话默认名要有信息量：用首条用户消息截断 40 字符，而不是 "Verify chat"。
- 行高：标题 + 一行预览 → **64pt**；两行预览 → 78pt。

**FAB 基本对**，实测 58pt 紫色圆形、右下。微调：直径 **56pt**，右/下各
**16pt**（下缘在 safe area 之上 16pt，现在贴得偏近），投影
`0 4pt 12pt rgba(0,0,0,0.18)`，`plus` 用 22pt semibold SF Symbol。

### 1.3 对话页

**疑似渲染 bug：助手回复出现在用户消息上方。** 浅色截图里 "pong" 在
y≈130，用户气泡在 y≈159–197。时序必须严格自上而下（用户先发、助手后回），
这反过来就是错的，先修这个再谈样式。

**导航栏：标题叫 "Message"，等于没有标题。** 应是：会话名（17pt semibold
居中）+ 副标题（12pt 灰：bot 名 · 连接状态/正在输入）。且导航栏现在是
不透明白底 + 一条生硬的分隔线，与下方灰色聊天区 (242,242,247) 形成两段
色块——应该用**默认的半透明毛玻璃**（scrollEdgeAppearance 不设，让内容
滚到栏下时自然模糊）。返回 chevron 用默认蓝色即可，现在是紫色，保持系统
蓝更符合"导航是系统控件"的直觉（品牌色克制原则）。

**助手消息：裸文本全宽是对的**（为 markdown/代码块预留），但现在：

- 左边距实测 18pt，与用户气泡的 16pt 右缘不对齐——统一 **16pt**；
- 没有消息时间；长会话里需要在消息组之间插时间分隔（13pt 灰居中，
  间隔 >10 分钟或跨天时出现）；
- "pong" 这种短回复在满屏留白里**没问题**（Messages 也是这样），问题在
  于它没有任何"这是 agent 说的话"的归属感——靠 16pt 对齐 + 段落排版 +
  后续的工具卡片就能解决，不要给它加气泡。

**用户气泡：** 紫色实测 #7755FF（品牌 #7C5CFF，OK），白字 17pt，圆角
≈19pt 连续曲率，右缘距屏 16pt ✓。补充规格：

- 内边距：**上下 10pt / 左右 14pt**
- 最大宽度：**屏宽 × 78%**（≈314pt），超过换行
- 与同侧上一条消息间距 **4pt**，与对侧消息间距 **16pt**
- 不要尾巴（iMessage 尾巴是拟物残留，现代客户端都不做了）

**Stop 按钮位置错误。** 一个红色文字的胶囊悬浮在屏幕中下方（y≈763），
既不像系统控件，又遮挡内容区。iOS 惯例：生成中时**发送按钮变成停止按钮**
（同一位置，`stop.square.fill` 或 `stop.circle.fill`），用户心智模型是
"那个箭头的位置现在可以停"。辅助手段：导航栏副标题变成 "正在生成…"。

**输入栏不合格的细节：**

- 发送按钮**常灰**（实测底 (237,237,239)、箭头 (179,179,183)），有文字
  时也是灰的——看起来永远禁用。规则：无文字 → 灰色圆形 + 灰箭头；有文字
  → **品牌紫圆形 + 白色 `arrow.up`**。这是 0 成本、感知极强的一改。
- 输入框胶囊高 41pt，应 **36pt 起步、随内容自增到 ~120pt（5 行）**，
  圆角 18（半高）。
- 输入栏底色用不透明灰（现在是 (242,242,247) 一片），应为毛玻璃
  （systemMaterial）+ 顶部 0.5pt 分隔线，内容滚动时能透出。

## 2. 缺失状态的设计

### 2.1 空态（首页无会话 / 空对话）

首页空态（现在是大菊花的位置）：

```
        ┌─────────────┐
        │  💬 60pt    │   ← SF Symbol bubble.left.and.bubble.right,
        └─────────────┘        品牌紫 30% 透明度圆底 96pt
     还没有会话
     17pt semibold，label 色
     你的 agent 7×24 在线，发句话它就开始干活。
     15pt 灰，居中，两行内
        [ 新建会话 ]   ← 品牌紫描边按钮，高 40pt，圆角 20
```

整体垂直居中偏上（屏幕 42% 高度处），FAB 仍在右下不冲突。

空对话（进了会话还没消息）：顶部居中灰字 13pt "这是与 {bot} 的新会话"，
下方 2–3 个**建议操作胶囊**（13pt，secondarySystemFill 圆角 16，如
"看看桌面上的文件"、"今天跑了什么任务"），点击即发送。

### 2.2 有内容的会话列表（含运行中 / 待审批）

```
│ ● 修复登录页样式            12:40  │  ← 标题 17pt med，时间 13pt 灰
│ ⟳ 正在执行: npm run build…         │  ← 预览 15pt 灰，运行中前缀转轮
│──────────────────────────────────│
│ ◐ 数据迁移                审批 ⏸   │  ← 等待审批：右侧不显示时间，
│ ● Run "rm -rf tmp"?              │    显示橙色"审批"胶囊(11pt 白字/
│                                  │    systemOrange 底)，预览为待批内容
│──────────────────────────────────│
│ ○ 周报汇总                  昨天   │  ← 空闲：无状态点或灰点
│ 好的，周报已生成并发到…            │
```

- 状态点（标题左侧 8pt 圆点）：绿=运行中（带 1s 呼吸），橙=等审批（常亮），
  无=空闲。
- 正在运行的会话，预览文字尾部 spinner（12pt）替代静态省略号。
- 左滑删除（红）、右滑置顶（灰）；删除需确认 alert。

### 2.3 待审批聚合区（首页顶部）

位置：**导航栏之下、列表之上**，inset 16pt 卡片，视觉权重高于列表行低于
导航。这是全 App 唯一允许用橙色的地方（与品牌紫区隔"需要你"和"常规"）。

折叠态（默认，高 44pt）：

```
┌────────────────────────────────────────┐
│ ⏸ 3 个会话等待你的审批           3 ▸  │
└────────────────────────────────────────┘
```

systemOrange 图标 + 17pt med 黑字 + 右侧计数胶囊（橙底白字 13pt）。

展开态（点按展开，spring 动画）：

```
┌────────────────────────────────────────┐
│ ⏸ 3 个会话等待你的审批           3 ▾  │
│────────────────────────────────────────│
│ Claude · refactor-auth        2分钟前  │
│ 执行 "npm test"?        [拒绝] [允许]  │
│────────────────────────────────────────│
│ Codex · data-migration        5分钟前  │
│ 删除 23 个文件?         [拒绝] [允许]  │
│────────────────────────────────────────│
│ 查看全部 3 条                       ▸  │
└────────────────────────────────────────┘
```

- 每条：bot 名 · 会话名（13pt 灰）/ 待批内容一行截断（15pt）/
  两个按钮（[拒绝] 灰底 15pt、[允许] **橙底白字** 15pt，各 60×30pt，圆角 15）。
- 最多展开 3 条，更多走"查看全部"进审批列表页。
- 允许/拒绝后该行以 0.25s 收缩消失，计数同步减；全部处理完整张卡
  0.3s 折叠消失。允许成功给 `UINotificationFeedbackGenerator` success
  震动——**这是全 App 最重要的一次触觉反馈**。
- 点卡片非按钮区域 → 进入该会话并定位到审批卡片。

### 2.4 消息流内的特殊块

**思考过程块**（默认折叠）：

```
┌────────────────────────────────────────┐
│ 💭 思考了 12 秒                     ▸  │  ← 13pt 灰，斜体不用
└────────────────────────────────────────┘
```

折叠行高 32pt；展开后等宽灰字 13pt、行高 1.4、max 高度 240pt 内滚。
生成中标题变 "正在思考…" + 左侧三点动画。

**工具调用卡片**（三种状态共用骨架）：

```
┌────────────────────────────────────────┐
│ ⌘ Bash                      ⟳ 执行中   │  ← 头行 40pt：SF Symbol 15pt +
│────────────────────────────────────────│    工具名 15pt semibold + 右侧状态
│ $ npm run build                        │  ← 内容 SF Mono 13pt，最多 3 行
│ ✓ added 214 packages in 6s             │    超出"展开"，失败时自动展开
└────────────────────────────────────────┘
```

inset 16pt、圆角 12、底 secondarySystemGroupedBackground、0.5pt 分隔线描边、
内边距 12。状态色：执行中=转轮+灰字，完成=绿 `checkmark`，失败=红
`xmark` + 卡片描边变 systemRed 30%。

**文件改动卡片**：

```
┌────────────────────────────────────────┐
│ 📝 修改了 3 个文件                  ▸  │
│────────────────────────────────────────│
│ src/login.tsx          +42  −18        │  ← 文件名 14pt med，
│ src/api/client.ts      +10   −2        │    +绿 −红 SF Mono 13pt
│ docs/review.md         +128   −0       │
└────────────────────────────────────────┘
```

**附件**：图片 4:3 圆角 12 缩略图（max 240pt 宽），文件用 56pt 高行
（图标 + 文件名 + 大小 13pt 灰）。

**错误 / 中断**：

```
┌────────────────────────────────────────┐
│ ⚠️ 连接中断，这条回复可能不完整。       │
│                              [重试]    │
└────────────────────────────────────────┘
```

贴在该条助手消息之后，systemRed 图标 + 15pt 灰字 + 灰底重试按钮；
整条消息不打红底（太吵）。

### 2.5 连接中断 / 重连中 / 视图过期

- **重连中**：导航栏副标题（bot 名下方/右侧）变 "重连中…" 13pt 橙 +
  橙色状态点；**不要**在内容区放菊花。中断 >5s 再在内容区顶部插入一条
  44pt 横幅（橙底 10% + 深橙字 14pt "连接已断开，正在重连"），恢复后
  0.3s 收起。输入框保持可用（消息排队，气泡右下角带时钟标记，发出后
  转正常）。
- **视图过期（收到 seq 空洞 / runtime_dropped 重订阅取快照中）**：
  内容区顶部 32pt 灰条 "正在同步最新消息…" + 转轮；已有内容**不清空、
  不闪**，快照回来后按序合并。
- **发送失败**：气泡右下角红 `!` 圆圈，点击 action sheet：重发 / 删除。

## 3. 下一轮设计规格（实现向）

### 3.1 首页

```
┌─ 导航栏（半透明毛玻璃，大标题模式）──────────┐
│ ○                                          │ ← 右上：连接状态点 10pt
│ Sessions                                   │ ← 大标题 34pt Bold
│ 🤖 iOS Dev ⌄                               │ ← 副标题 13pt 灰，可点切 bot
├────────────────────────────────────────────┤
│ [待审批聚合卡，见 §2.3，无审批时不占位]        │
├────────────────────────────────────────────┤
│ ● 标题 17pt med              12:40  [审批] │
│   预览 15pt 灰，1 行截断                   │  行高 64pt
│ ────────────────────────────────────────── │  分隔线 0.5pt，左缩进 16pt
│ ○ …                                        │
└────────────────────────────────────────────┘
                                    ┌────┐
                                    │ +  │  56pt 品牌紫，右下 16/16
                                    └────┘
```

- 背景 systemGroupedBackground，列表卡片感靠行底
  secondarySystemGroupedBackground？不——会话列表用 **plain 样式**
  （行与背景同色，只靠 0.5pt inset 分隔线），像 Messages，不要 inset
  grouped 卡片。
- 下拉刷新：标准 UIRefreshControl。
- 空态见 §2.1；加载中首屏用**骨架行**（3 行灰色圆角条占位），不用菊花。

### 3.2 对话页

```
┌─ 导航栏（毛玻璃，内容滚到栏下）──────────────┐
│ <       修复登录页样式            ⋯         │
│         iOS Dev · 在线                      │ ← 12pt 灰副标题
├────────────────────────────────────────────┤
│              今天 21:30                     │ ← 时间分隔 13pt 灰
│                                            │
│  助手全文文本，16pt 边距，17pt/22 行高        │
│  ┌─ 工具卡片（见 §2.4）─────────────────┐  │
│  └──────────────────────────────────────┘  │
│                     ┌───────────────────┐  │
│                     │ 用户气泡            │  │ 紫底白字，圆角 18，
│                     └───────────────────┘  │ 内边距 10/14，max 78%
│                                            │
│  [思考块 / 工具卡片 / 文件卡片按时间序混排]    │
├────────────────────────────────────────────┤
│ ┌──────────────────────────┐  ┌────┐      │
│ │ Message                  │  │ ↑  │      │ ← 输入区，毛玻璃底
│ └──────────────────────────┘  └────┘      │
└────────────────────────────────────────────┘
```

数值表：

| 元素       | 规格                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| 助手正文   | 17pt，行高 22，段落间距 8，边距 16                                         |
| 助手代码块 | SF Mono 15，底 tertiarySystemFill，圆角 8，内边距 10，横向滚动             |
| 用户气泡   | 17pt 白，品牌紫底，圆角 18，内边距 10v/14h，max 宽 78%                     |
| 消息间距   | 同侧连续 4pt，异侧 16pt，时间分隔上下各 20pt                               |
| 工具卡片   | inset 16，圆角 12，内边距 12，头行 40pt，正文 Mono 13                      |
| 输入框     | min 36pt / max 120pt 自增，圆角 18，tertiarySystemFill 底                  |
| 发送按钮   | 28pt 圆，空=灰底灰箭头，有字=紫底白 arrow.up 20pt，生成中=紫底白 stop icon |
| 跳转底部   | 距底 >200pt 时浮出 36pt 圆钮 `chevron.down` + 未读数，右对齐 16pt          |

**滚动行为**：新消息到达时，若滚动位置距底部 <60pt → 贴底跟随（无动画
或 0.1s）；>60pt → 不动，浮出"回到底部"按钮。用户正在上滑阅读时**绝不**
自动滚动。

### 3.3 动效与流式文本

| 场景               | 动效                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------- |
| 流式文本追加       | **无动画**。按 id upsert，禁用隐式动画直接布局；每个 delta 不触发 fade/位移。禁止整块 replace（会闪） |
| 生成开始/结束      | 工具卡片状态 icon 交叉淡化 0.2s；发送→停止按钮 morph 0.15s scale                                      |
| 新消息（完整到达） | 上移 + 淡入，spring response 0.35 / damping 0.85                                                      |
| 审批卡出现/消失    | 高度 spring 展开收起 0.3s，与列表同步布局动画                                                         |
| 连接横幅           | 高度 0.25s easeInOut 插入/移除                                                                        |
| 列表行删除/插入    | UITableView automatic（0.25s）                                                                        |
| 触觉               | 审批通过=success，工具失败=warning，发送=无（太频繁）                                                 |

**流式不闪不跳的三条铁律**：① 追加只改文本存储，不重建 cell；② 自动
滚动只调 contentOffset，不动画；③ 文本渲染宽度稳定——等宽字体只用于
代码块，正文不换字体，避免逐 token 重排时整段跳动。

---

## 4. 必须用 Swift 原生实现的清单（按 ROI 排序）

1. **消息流**：UICollectionView + TextKit 2 / 原生文本渲染。
   理由：流式 upsert 的 60fps、文本选择/复制、链接与代码块混排、滚动
   性能，RN FlatList 每一项都做不到位；这是用户 90% 时间所在的屏。
2. **输入器 + 键盘联动**：原生 UITextView 自增高、inputAccessoryView、
   交互式键盘手势（下滑收键盘与滚动耦合）。
   理由：键盘跟手是"原生感"最敏感的测试点，RN 的 keyboard avoiding
   永远差半拍。
3. **消息长按 Context Menu + 触觉**：UIContextMenuInteraction（复制/
   重发/引用）+ 审批的 success/warning haptics。
   理由：投入极小（几百行），感知极强；RN 仿不出来 context menu 的
   预览动画。
4. **待审批聚合区**：可以用 RN 先跑通，但其展开动画 + 震动 + 实时
   计数若要达到 §2.3 的质感，值得原生。**本轮先 RN，下轮视情况。**
5. **会话列表**：RN 可以做好（纯文本行 + 左滑），**不着急原生**；等
   消息流原生化了再顺手迁。

登录页、空态、错误横幅：留 RN，把样式改对即可。

## 5. 三个最高优先级建议

**① 建立间距与层级的数值体系，先改登录页和首页的行结构。**
现在最大的"不像原生"来源不是颜色不是圆角，是分组逻辑错误（组间距小于
组内距）、全宽分隔线、标题层级缺失。把 §3 的数值表落成一组 design
token（间距 4/8/16/24/32、字号 13/15/17/34、语义色只用系统角色），
两个静态屏一天就能改完，观感立刻上一个台阶。

**② 修对话页的"状态语言"：导航副标题 + 发送/停止按钮一体 + 毛玻璃栏。**
发送按钮常灰、Stop 悬浮中屏、标题叫 "Message"、导航栏不透明——这四件
事每件都是小改，合起来决定了用户是否觉得"这是 iOS 应用还是网页套壳"。
其中发送按钮随内容变紫是零成本项，先做。

**③ 把流式渲染的原生消息流排上日程，并先按 §3.3 定死"不闪不跳"规格。**
它是核心体验，也是 RN 与原生差距最大的地方；即使原生版本还没排期，
现在 RN 版也要按"追加不重建、滚动不动画"重写，否则后面工具卡片、
审批卡全都要在错误的地基上返工。

---

## 6. 一句话总结

**这版离 Lody 那种质感，最缺的是"材质与层次"**——现在屏幕上只有两种
东西：纯色块和字；而原生 iOS 的质感来自毛玻璃导航栏下滚过的内容、
inset 分隔线划出的分组、灰阶五级背景（grouped/secondary/tertiary/fill）
叠出的纵深，以及状态驱动的微动效。把这些"不要钱的系统材质"用上，比
再调任何颜色都更接近目标。
